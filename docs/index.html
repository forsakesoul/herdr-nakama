The crew

OWNER / WORKER / ADVISOR
01

Owner · captain

Investigates, freezes the handoff and accepts the result. Never writes project code.

02

Worker · crew at work

The only one who changes code. Reports back when done, blocked or out of context.

03

Advisor · navigatoroptional

Optional. Checks the plan and reviews the diff independently.

Three steps to your first crew

  1. 1

    Install the plugin and create your private config (never committed).

    bash
    herdr plugin install forsakesoul/herdr-nakama
cfg="$(herdr plugin config-dir forsakesoul.nakama)/config.json"
[ -e "$cfg" ] || (umask 077 && mkdir -p "${cfg%/*}" && \
  curl -fsSL https://raw.githubusercontent.com/forsakesoul/herdr-nakama/main/config.example.json -o "$cfg.tmp" && mv "$cfg.tmp" "$cfg")
  2. 2

    Bind two keys in ~/.config/herdr/config.toml, then herdr server reload-config.

    config.toml
    [[keys.command]]
key = "prefix+u"
type = "plugin_action"
command = "forsakesoul.nakama.pick"

[[keys.command]]
key = "prefix+i"
type = "plugin_action"
command = "forsakesoul.nakama.init"
  3. 3

    In a project pane press prefix+u, pick the engines and confirm. When the agents are up, press prefix+i.

After a restart, the same crew

Herdr or the computer restarted and every terminal ID changed? Preflight first — read-only, zero writes — then confirm to bind the team again. Nothing is renamed or resent behind your back.

bash
nakama rebind --team <id> --preflight
nakama rebind --team <id> --confirm-anchor <terminal>

Change the crew mid-voyage

Add or drop the Advisor, or replace a stuck Worker, from the same prefix+u menu. Handoffs and reviews are written as files in a per-task directory, so a newcomer reads the latest handoff instead of asking around — and nothing is deleted until you say so.

bash
nakama add   --team <id> --engine <engine>
nakama swap  --team <id> --role worker
nakama clean --team <id> --task <task_id>

Why “Nakama”

Nakama (仲間) is what Luffy calls his crew in One Piece: companions who each own part of the voyage. And like a Vivre Card pointing home, nakama rebind finds every member again after a storm.

三步组建你的第一支船团

  1. 1

    安装插件，生成私有配置（不入库）。

    bash

cfg="$(herdr plugin config-dir forsakesoul.nakama)/config.json"

  curl -fsSL https://raw.githubusercontent.com/forsakesoul/herdr-nakama/main/config.example.json -o "$cfg.tmp" && mv "$cfg.tmp" "$cfg")
  2. 2

    在 ~/.config/herdr/config.toml 绑定两个快捷键，然后 herdr server reload-config。

    config.toml
    [[keys.command]]

[[keys.command]]
key = "prefix+i"
type = "plugin_action"
command = "forsakesoul.nakama.init"
  3. 3

    在项目 pane 按 prefix+u，选好引擎并确认；agent 起好后按 prefix+i。

重启之后，还是那支船团

电脑或 Herdr 重启、终端编号全变了？先预检（只读、零写入），确认后重新绑定。不会背着你改名或重发任何消息。

bash
nakama rebind --team <id> --preflight
nakama rebind --team <id> --confirm-anchor <terminal>

航行中途，也能换人

在同一个 prefix+u 菜单里加入或移除 Advisor，或替换卡住的 Worker。交接包和审查结论按任务写成文件，新来的伙伴直接读最新交接，不用别人转述；这些文件在你明确说可以删之前不会被清理。

bash
nakama add   --team <id> --engine <engine>
nakama swap  --team <id> --role worker
nakama clean --team <id> --task <task_id>

为什么叫 Nakama

Nakama（仲間）是《海贼王》里路飞对船员的称呼：各自负责一段航程的伙伴。就像指向主人的生命卡，nakama rebind 会在风暴过后把每位伙伴找回来。

一味の役割

OWNER / WORKER / ADVISOR
01

Owner · 船長

調査し、引き継ぎを確定し、結果を受け入れます。プロジェクトのコードは書きません。

Worker · 手を動かす船員

任意。方針を検証し、diff を独立にレビューします。

3 ステップで最初の一味を

  1. 1

    プラグインをインストールし、非公開の設定を作成します（コミットしません）。

    bash
    herdr plugin install forsakesoul/herdr-nakama
cfg="$(herdr plugin config-dir forsakesoul.nakama)/config.json"
[ -e "$cfg" ] || (umask 077 && mkdir -p "${cfg%/*}" && \
  curl -fsSL https://raw.githubusercontent.com/forsakesoul/herdr-nakama/main/config.example.json -o "$cfg.tmp" && mv "$cfg.tmp" "$cfg")
  2. 2

    ~/.config/herdr/config.toml にキーを 2 つ割り当て、herdr server reload-config を実行します。

    config.toml
    [[keys.command]]
key = "prefix+u"
type = "plugin_action"
command = "forsakesoul.nakama.pick"

[[keys.command]]
key = "prefix+i"
type = "plugin_action"
command = "forsakesoul.nakama.init"
  3. 3

    プロジェクトの pane で prefix+u を押してエンジンを選び確定。エージェントが起動したら prefix+i。

再起動しても、同じ一味

Herdr やコンピューターが再起動して terminal ID がすべて変わっても大丈夫。まずプリフライト（読み取り専用・書き込みゼロ）、確認してから再バインドします。勝手に改名や再送はしません。

bash
nakama rebind --team <id> --preflight
nakama rebind --team <id> --confirm-anchor <terminal>

航海の途中でも、仲間を入れ替えられる

同じ prefix+u のメニューから Advisor を追加・削除したり、止まった Worker を交代させたりできます。引き継ぎやレビューの結論はタスクごとのディレクトリにファイルとして残るので、新しい仲間は最新の引き継ぎを直接読めます。削除してよいと言うまで、これらのファイルは消えません。

bash
nakama add   --team <id> --engine <engine>
nakama swap  --team <id> --role worker
nakama clean --team <id> --task <task_id>

なぜ「Nakama」なのか

Nakama（仲間）は『ONE PIECE』でルフィが船員を呼ぶ言葉です。ビブルカードのように、nakama rebind は嵐のあとで仲間を一人ひとり見つけ出します。
